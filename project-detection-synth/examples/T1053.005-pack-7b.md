# Detection pack — T1053.005 Scheduled Task
*Platforms: Windows · grounded on 1 MITRE analytic(s)*

## Example procedures
1. The adversary uses the `schtasks` command to create a new scheduled task under the SYSTEM context to execute a malicious payload every system startup.

2. The actor writes a PowerShell script to modify existing scheduled tasks, adding a new action to nomad.exe with a high entropy command line argument, and schedules it to run daily.

3. The threat actor leverages the Windows Task Scheduler API to create a hidden task that runs a custom .NET executable under the Local Service account at irregular intervals.

## Detection telemetry
- **Log/Event Sources:**
  - `Security`: For detection of task creation, modification, and deletion.
  - `System`: For detection of task execution.
  - `Microsoft-Windows-Security-Auditing`: For more detailed auditing.

- **Key Fields:**
  - `EventID`: 4697 (Scheduled Task Created), 4698 (Scheduled Task Modified), 4699 (Scheduled Task Deleted).
  - `User` (SubjectUserName): To identify the context of the task creation/modification/deletion.
  - `TaskName`: The name of the scheduled task.
  - `CommandLine`: The command line used to create or modify the task.
  - `TaskPath`: The path where the scheduled task is stored.
  - `ParentProcessGuid`, `ParentProcessId`, `ParentImage`: To identify the parent process chain.

- **Example Command-Lines or Event IDs yy-mm-dd hh:mm:ss:**
  - `4697`: `2023-10-01 14:30:00 - schtasks /create /tn "UpdateService" /tr "C:\path\to\malware.exe" /sc DAILY /ru SYSTEM`
  - `4698`: `2023-10-01 14:35:00 - schtasks /change /tn "UpdateService" /st 00:00 /ru SYSTEM`
  - `4699`: `2023-10-01 14:40:00 - schtasks /delete /tn "UpdateService" /f`

- **Parent/Child Process Chains:**
  - Example: 
    - `svchost.exe` -> `taskeng.exe` -> `malware.exe`
    - `explorer.exe` -> `powershell.exe`
